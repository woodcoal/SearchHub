# 日志与用量统计

SearchHub 有两套日志，视角不同，不要混淆：

| | 运行日志 | 调用日志 |
|---|---|---|
| 视角 | **服务视角**——启动、报错、搜索事件 | **搜索视角**——每一次密钥 / 供应商尝试 |
| 文件 | `searchhub-YYYY-MM-DD.log`（按天） | `calls.jsonl`（JSONL，一行一条） |
| 粒度 | 每次搜索一条 | 每次**尝试**一条（一次搜索可能有多条） |
| 用途 | 排障、看服务状态 | 分析命中率、密钥健康度、降级链路 |

默认都放在 `<SEARCHHUB_HOME>/log/`，可用 `SEARCHHUB_LOG_DIR` 改。

---

## 运行日志

- 文件名为 `searchhub-YYYY-MM-DD.log`，**跨天自动切换，无需额外轮转组件**。
- 每次搜索都会写一条结构化日志（`event: search`），包含：检索词、命中供应商、使用的密钥、结果条数、耗时、尝试次数、是否降级。**成功与失败都记录。**
- 保留天数由 `SEARCHHUB_LOG_RETENTION_DAYS` 控制，默认 **14 天**；设为 `0` 表示永久保留。
- 清理时机：每次**服务启动**时，以及执行 `searchhub logs --prune` 时。
- **按文件名中的日期判断是否过期，不依赖文件 mtime**——避免文件被复制、同步或备份工具改写 mtime 之后导致误删或漏删。
- 默认同时输出到控制台，便于 `docker logs`。设为 `SEARCHHUB_LOG_STDOUT=false` 则只写文件。
- 日志中的 **API Key、管理令牌、密钥原文、登录密码统一做了 redact 脱敏**。

管理后台「日志」页可以直接查看：

- 按天选择日志文件（默认今天），列出所有历史文件并可一键切换
- 按级别过滤（INFO / WARN / ERROR 及以上）
- 按关键词过滤（检索词、供应商、消息）
- 「仅搜索事件」开关：只看搜索，或查看包含启动、报错在内的全部运行日志
- 自动刷新（5 秒），方便边压测边观察
- 每行的 ⋯ 可以展开该条的完整原始 JSON

```bash
searchhub logs              # 查看日志目录、保留策略与文件占用
searchhub logs --prune      # 立即清理过期日志
```

接口：`GET /api/admin/logs?date=2026-09-21&level=warn&onlySearch=true&keyword=openai&limit=200`

## 调用日志（持久化）

每次密钥 / 供应商尝试写一条，含时间、供应商、密钥、成功与否、故障码、耗时。落盘在 `<logDir>/calls.jsonl`。

设计上的几个取舍：

- **重启不清零**：启动时自动加载文件尾部的记录，并按实际继续追加；内存与文件都保留最近 **1000 条**。
- **文件有界**：追加满一轮（1000 条）后整体重写一次，文件稳定在 **1000~2000 行**，不会无限增长。
- **读取有上限**：只取文件尾部 **2MB**；损坏的行自动跳过，不影响其余历史。
- **写失败静默忽略**——日志绝不能拖垮搜索主流程。

管理后台「日志」页顶部的「调用记录（持久化）」区块可查看，支持最近 **50 / 200 / 1000** 条切换。
首页的「调用日志」区块与它是同一份数据（首页只取最近 30 条）。

接口：`GET /api/admin/calls?limit=1000`（`limit` 上限 1000，返回 `file`、`total`、`entries`）

## 用量统计

「用量统计」页按**尝试次数**汇总每个供应商与每把密钥的使用情况：

- **概览**：总调用、成功、失败、成功率、平均耗时
- **趋势**：最近 24 小时（按小时）与最近 14 天（按天）的柱状图，红色部分表示失败
- **分供应商**：命中次数、成功率、平均耗时、最近成功时间、最近错误
- **分密钥**：每把密钥的调用 / 成功 / 失败 / 成功率 / 平均耗时 / 最近使用时间 / 最近错误——可以快速发现"某把 key 一直没被用到"或"某把 key 频繁失败"

**统计口径是尝试次数**：一次搜索可能包含换密钥、换供应商的多轮尝试，每一轮都会分别计数；「无可用密钥」「供应商熔断被跳过」也会记录，便于定位容量问题。

```bash
searchhub usage
searchhub usage --json
```

接口：`GET /api/admin/usage`

> 用量统计保存在**进程内存**中，重启清零。多实例部署需要换成 Redis 实现——接口已按可替换设计，详见 [limitations.md](./limitations.md)。
