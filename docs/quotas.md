# 配额与限流

每把供应商密钥都可以独立控制用量。系统用**三级配额**加一个**QPS 令牌桶**共同约束，任一维度触顶都会立刻生效，不需要重启。

## 三级配额

| 配额 | 字段 | 说明 | 重置方式 |
|---|---|---|---|
| 日配额 | `dailyQuota` | 当天累计调用上限 | 每天 **UTC 0 点**自动归零 |
| 月配额 | `monthlyQuota` | 当月累计调用上限 | 每月 **1 号 UTC 0 点**自动归零 |
| 总配额 | `totalQuota` | 累计调用上限（如一次性购买的额度包） | **不随时间恢复**，需调高配额或「重置用量」 |

三类配额互不冲突，可以同时设置；**留空表示不限**。

任一配额用尽，该密钥立即进入**隔离**状态，并自动切换到同一供应商的其它可用密钥。管理界面上可以直接看到 `已用 / 上限` 三个数字，也可以用「重置用量」清零（例如充值之后）。

## QPS 令牌桶

除配额之外，每把密钥还有一个独立的 QPS 令牌桶，用于控制**瞬时速率**——配额管的是"总量"，QPS 管的是"速度"。

## 内置默认配额

首次启动时，各供应商会带一组**面向免费额度**的默认值，目的是避免默认配置在一次压测里就把免费额度烧完。

（QPS 与配额按各家免费额度设置；官方未明确说明的，QPS 取 5。）

| 供应商 | 全局 QPS | 日配额 | 月配额 | 总配额 | 依据 |
|---|---|---|---|---|---|
| `anysearch` | **20** | **1000** | 不限 | 不限 | 免费额度：QPS 20、日限额 1000 |
| `exa` | **10** | 不限 | **1000** | 不限 | 免费额度：QPS 10、月限额 1000 |
| `serper` | **5** | 不限 | 不限 | **2500** | QPS 官方未明确，取 5；免费为一次性 2500 credits，且不按月重置 |
| `tavily` | **5** | 不限 | **1000** | 不限 | QPS 官方未明确，取 5；免费 1000 credits/月（basic 搜索计 1 credit） |

关于这组默认值：

- 它们是**供应商级**默认值。密钥里留空的字段会继承，也可以在「供应商配置」里按实际套餐修改。
- **日配额只给 `anysearch` 设置了**（它明确按日限额），其余三家一律「不限」，只受 QPS 与月 / 总配额约束。
- 升级已有数据文件时按 `quotaSeedVersion` 做迁移：**只有当前值仍等于上一版内置默认值时才覆盖**。你在界面上手动改过的值一律保留。

## 供应商级全局默认

「供应商配置」里可以给该供应商设置**全局 QPS 与三类配额**，作为该供应商下所有密钥的兜底：

- 密钥里**留空**的 QPS / 配额字段会继承供应商的全局设置（界面上以「继承」标记提示）
- 密钥里**显式填写**的值优先于全局设置
- 全局与密钥**都留空**，则表示不限

这样常见的做法是：先给某个供应商统一设一个安全水位（例如全局 1 QPS、日 3000），再对个别密钥单独调高——避免每加一把密钥都要重复填一遍参数。

## 相关接口与命令

```bash
searchhub keys add serper '<key>' --label 主key --qps 2
searchhub keys update serper 主key --daily-quota 1000
searchhub keys reset-usage serper 主key     # 清零用量并解除隔离
searchhub usage                             # 分供应商 / 分密钥的用量统计
searchhub usage --json
```

对应接口：`POST` / `PATCH /api/admin/keys[/...]`、`GET /api/admin/usage`。
